[1] STM32 ZEPHYR SHELL COMMANDS (Interactive Terminal: screen /dev/tty.usbmodem* 115200)
--------------------------------------------------------------------------------

1. System Status & Diagnostics:
   hil status
     -> Get full HIL plant status in JSON format (FSM state, pressure_kpa, pump_duty,
        leak, camera_scene, estop, valve_open, start_stop_io, etc.)

   hil test_interfaces
     -> Test all 5 hardware interfaces at once (I2C target 0x58, IO lines, PWM capture,
        DAC audio leak, and core status READY).

   hil loopback
     -> Execute I2C Master-to-Slave loopback self-test on STM32.

   hil reset
     -> Fully resets plant simulator to default IDLE (clears overrides, mutes DAC audio,
        stops Doctor Button to 0V, sets pressure back to ambient).

2. Doctor Start / Stop Controls (Drives PB13 to KR260 PMOD1 Pin 3):
   hil button start
     -> Drives PB13 to 3.3V (HIGH) to signal KR260 to start Vitis AI & PID loop.

   hil button stop
     -> Drives PB13 to 0.0V (LOW) to signal KR260 to stop procedure and deflate.

   hil button pulse [ms]
     -> Sends momentary HIGH pulse on PB13 (default: 200 ms) for edge-triggered KR260 setups.

   hil button status
     -> Returns current Doctor Button level in JSON: {"button": "START"|"STOP", "level": 1|0}.

   hil set_start_stop <0|1>
     -> Legacy alias for Doctor Button control (1 = 3.3V, 0 = 0V).

3. Clinical Named Scenarios:
   hil scenario <normal|low_pressure|over_expansion|gas_leak|tube_kink|cough_spike> [custom_val]
     -> Loads clinical scenario by name, sets medical starting conditions in C,
        and executes real-time differential equation physics dynamically.
        Examples:
          hil scenario normal           (Target 125 kPa, stable mucosal inspection)
          hil scenario low_pressure     (110 kPa, tests KR260 ramping up pump)
          hil scenario over_expansion   (152 kPa, tests emergency solenoid venting)
          hil scenario gas_leak         (125 kPa, drains at 22 kPa/s + 3 kHz DAC hiss)
          hil scenario tube_kink        (Flat 101.3 kPa, tests occlusion timeout)
          hil scenario cough_spike      (160 kPa transient spike)

4. FSM State & Physical Overrides:
   hil set_state <IDLE|INSUFFLATE|INSPECT|LEAK|DEFLATE|ESTOP>
     -> Manually force clinical state machine transition.

   hil set_pressure <float_value_in_kpa>
     -> Manually inject fixed pressure value (e.g. 'hil set_pressure 125.5'). Disables auto-sim.

   hil inject_leak <0|1>
     -> 1 = Injects sudden chamber leak + activates 3 kHz DAC hiss on PA4.
        0 = Clears leak condition and returns to normal pumping.

   hil audio_leak <0|1>
     -> 1 = Turns on DAC1 3 kHz acoustic leak sound waveform on PA4.
        0 = Mutes DAC1 output to 0V.

   hil set_solenoid <0|1>
     -> 1 = Solenoid Valve OPEN / Venting (Over-Expansion deflation).
        0 = Solenoid Valve CLOSED / Holding pressure.

   hil set_estop <0|1>
     -> 1 = Asserts Emergency Stop (instant shutdown, PWM 0%, valve open).
        0 = Clears Emergency Stop.


================================================================================
[2] PYTEST AUTOMATED COMMANDS (Host Laptop Testbench)
================================================================================

1. Make Targets (Fastest Execution):
   make test-button
     -> Runs only Doctor Start/Stop button test (test_08_mock_doctor_button).

   make test-scenarios
     -> Runs all Data-Driven Clinical Scenarios defined in tests/clinical_scenarios.json
        (HIL-TC-01 through HIL-TC-06).

   make test-interfaces
     -> Runs only interface diagnostics test (test_07_test_interfaces).

   make test
     -> Runs complete test suite (test_01 to test_08) and generates reports/test_results.csv.

   make test-setup
     -> Automatically creates .venv, installs requirements.txt, and executes full test suite.

   make clean-test
     -> Cleans pytest cache and deletes previous test_results.csv reports.

2. Direct Pytest CLI Commands (Using Virtual Environment):
   source .venv/bin/activate

   # Run full test suite with verbose output:
   pytest tests/ -v -s --csv=reports/test_results.csv

   # Run individual test cases:
   pytest tests/test_hil_stm32.py -k test_01_read_hil_status -v -s
   pytest tests/test_hil_stm32.py -k test_02_manual_pressure_override -v -s
   pytest tests/test_hil_stm32.py -k test_03_state_transitions -v -s
   pytest tests/test_hil_stm32.py -k test_04_gas_leak_injection -v -s
   pytest tests/test_hil_stm32.py -k test_05_mock_control_ios -v -s
   pytest tests/test_hil_stm32.py -k test_07_test_interfaces -v -s
   pytest tests/test_hil_stm32.py -k test_08_mock_doctor_button -v -s

[3] FIRMWARE BUILD & FLASH COMMANDS
================================================================================

   make build
     -> Pristine clean build (west build -p always -b nucleo_h563zi .)

   make build-inc
     -> Incremental fast compilation (west build -b nucleo_h563zi .)

   make flash
     -> Self-healing flash (kills serial locks on macOS + auto-fallbacks to MSD if SWD locked)

   make flash-msd
     -> Direct fast copy flash to Nucleo USB drive (bypasses STM32CubeProgrammer)

   make build-flash
     -> Pristine compile + flash in a single command
